# Car/Home：可复现的实验框架

研究问题：固定基线助手面对完整 MatrAIx 原生 persona，在不同披露方式和当前优先项下，
能否通过交互正确完成程序可验证的任务。四个条件是同一身份的情境操纵，不是四份新身份。
若只更换 SUT，可比较不同助手；若连 PUT 也更换，结论应针对整套交互系统。

## 设计与测量

- 车机与 Home 各六类任务，每类普通/边界两变体、四条件，源 persona 每场景48次独立会话。
- 原始 base pool 的来源、revision、名单、原始 YAML、完整属性和哈希随计划保存。
  按明确兼容性标准选人，不补值；记录来源类别，不能把合成画像直接视为真人验证。
- 主动披露和按需回答交叉时间/避收费（Car）或舒适/节能（Home）。任务事实与明确权限
  由程序控制；完整背景画像影响 PUT 的有限动作和风格。双方独立上下文，不跨案例记忆。
- 主指标是程序可验证的完整任务成功：实际模拟状态、时间/数值、偏好、范围和结构化提交
  均满足。可行部分完成、实际失败、缺失、未尝试分别统计，不评价自由文本心理逼真程度。
- 保留全部计划分母。缺失未知值按[0,1]保守界定，不假设 MCAR，不删完整案例。
  终态或回放成功不等于任务成功。空调分钟不是kWh，模拟计划不是实际道路执行。

## 四项预定总体对照

| 对照 | 左侧减右侧；先对各侧条件等权平均 |
|---|---|
| Car 披露 | (C1+C3) vs (C2+C4)，六任务 programmatic_task_success |
| Car 优先项 | (C1+C2) vs (C3+C4)，J1/J2/J3/J6 同指标 |
| Home 披露 | (C1+C3) vs (C2+C4)，六任务 programmatic_task_success |
| Home 优先项 | (C1+C2) vs (C3+C4)，H1/H5 preference_match |

按源 persona 整组配对 bootstrap，默认20,000次；种子、来源数、四项比较和唯一固定最终
检查在正式方案中冻结。四项 Bonferroni 整体 alpha=.05，单项双侧98.75%区间，覆盖率为近似。
八项条件内比较仅作描述，不能擅自追加显著性检验。区间触零或不显著不等于实际等效。
每人的48次会话不是48个独立样本；最低来源数和模板默认人数均非功效保证。

只有批准冻结、完整运行、原生回放和已知用量等门槛全部满足，才输出正式推断。
恢复调度不放宽这些门槛。缺失时保守描述；事后修订必须明确标注，保留原口径和记录。
不按中期结果改阈值、补样、挑比较或停止。

## Evidence insights

分别呈现 Car 和 Home：总体及预定对照 → 有价值的任务/条件细分 → 轨迹证据。
每条发现标明任务、条件、案例ID、操作、触发的约束及相关事件/状态，再提出可检验的
产品改进假设。重复 finding 按 episode/code 去重，不将相关标签相加冒充独立错误。

区分规划/配置与环境随时间达到并维持目标，也区分物理不可达、接口契约、越权和助手
决策问题。跨场景总体成功率受任务构成与完成层级影响，不直接解释为领域能力排名。
观察性轨迹解释不自动证明因果机制；改进版需另行实验。框架用于将 persona 条件与
可追溯产品风险联系起来，来源限制和协议边界应随结论说明。
